## 1. Audit scope

M6 closes the parent-facing administration vertical for screen-time policies: creating, editing, disabling, previewing the effective decision, granting temporary overrides with mandatory bounded expiry, and reviewing child exception requests. It deliberately excludes enforcement, usage measurement, and background services (M7/M8 territory), and makes no enforcement claims anywhere in the UI.

## 3. Contract reconciliation

The implementation reuses the deployed contracts without modification: `policyRepositoryProvider` (save/update/setEnabled/createOverride), `ChildExceptionRequestRepository` (create/approve/deny/forFamily with the atomic parent-review transaction), and `PolicyEngine.resolve` for the preview. One honest deviation was found and documented in the security evidence: the deployed ruleset (`e22c310a`) scopes `policy_overrides` writes to `parent(familyId)` but does not validate a mandatory `expiresAt` payload at rule level. The bounded-expiry invariant is therefore enforced client-side (repository validation plus the editor UI), and this is stated explicitly in the test harness rather than claimed as a rules-level property.

## 4. Change boundary

No modification was made to `PolicyEngine`, `ChildPolicyResolver`, `FamilyRuntimeContext`, `FamilyAuthorization`, `FamilyActorBindingService`, SQLite repositories, outbox internals, Firestore rules, or Functions. `analysis_options.yaml` was regenerated by the Flutter toolchain as part of the environment (unrelated to M6). Debug files created during iteration were deleted before the commit proposal.
