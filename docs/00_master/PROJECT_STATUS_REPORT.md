## 3. البنية التقنية

| الطبقة | التفاصيل |
|---|---|
| UI | Flutter 3.35.6، Material 3، Riverpod + hooks_riverpod، GoRouter (50 مسار + ShellRoute بتنقل سفلي 5 تبويبات) |
| التخزين المحلي | SQLite v17 (sqflite + sqflite_common_ffi للاختبار)، offline-first مع outbox |
| الواجهة السحابية | Firebase Auth + Firestore بعقود حقيقية في `firestore_contracts.dart` (FS-001: 5 حالات، FS-002: 6 حالات، FS-003: 4 حالات) |
| المزامنة | SyncCoordinator + OutboxSyncExecutor (تجربة فورية + إعادة جدولة) |
| الترجمة | AppLocalizations — عربية (RTL) + إنجليزية، ~1,143 مفتاح |
| التصاميم المولدة | شعار التطبيق + 4 صور onboarding مدمجة في الشاشة الرئيسية وشاشات LO-010 وWF-001 + خلفية إطلاق كحلية |

## 4. حالات التحقق (Validation)

### A. التحقق الهيدلس (flutter_tester) — تم جزئياً (بمعنى صادق)
- تم بناء harness (`headless_validation_test.dart`) يُقلع التطبيق الحقيقي (`GuardianApp`) للتنقل عبر 42+ مساراً باللغتين مع لقطات شاشة 1080×2400. harness التقط لقطات حقيقية (لوحة العائلة بالعربية والإنجليزية، نموذج إنشاء الجدار الجغرافي) وأثبت أن المسارات المبثوثة تبني شاشات فعلية.
- **النتيجة:** جميع الـ 282 اختبار أساس أخضر. **ملاحظة صادقة:** harness يتجمد عند أول مسار `'/'` داخل هذه البيئة (تكرار pumpAndSettle داخل flutter_tester يتوقف بالـ software rendering) — وهذا التجمد موجود حتى على التفرع النظيف قبل FS-003، أي أنه قيد في الأداة/البيئة وليس خللاً من كود FS-003. لم يصحَّح هنا؛ يُعالج عند اختبار الجهاز الحقيقي.
- **القيد:** لا يعادل اختبار Android حقيقي بأي شكل.

### B. التحقق على جهاز Android حقيقي — لم يتم
لا يوجد في هذه الجلسة جهاز Android حقيقي أو سحابة اختبار متاحة. APK قيد البناء الآن (انظر القسم 5).
