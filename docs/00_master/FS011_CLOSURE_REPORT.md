## 1. ملخص المرحلة

نفّذت هذه المرحلة **محرك السياسات المركزي (Family Rules & Policy Engine)** الذي يوحّد جميع قواعد العائلة في مكان واحد: إنشاء القواعد، جدولتها أسبوعيًا، استهداف أطفال محددين، كشف التعارضات وحلّها بالأولوية، تسجيل قرارات التنفيذ، وتطبيق القواعد بصدق دون ادعاء نجاح غير حقيقي.

اعتمدنا التصميم الموسع الذي أقرّه المستخدم: **7 أنواع قواعد حية + 3 أنواع محجوزة** تُفعَّل بربط بسيط عند وصول مراحلها (المهام FS-007، المكافآت FS-008، الأحداث FS-014)، دون الحاجة لإعادة بناء أي شاشة.

## 2. ما تم إنجازه

### 2.1 الشاشات السبع (FR-001 … FR-007)

| المعرف | الشاشة | الوظيفة |
|---|---|---|
| FR-001 | `rules_dashboard` | لوحة القواعد: جميع القواعد بحالتها الحقيقية (مفعّلة/متوقفة/متعارضة)، عداد التعارضات، الوصول بتفويض `FamilyRuntimeContext.can()` |
| FR-002 | `rule_builder` | منشئ القاعدة: النوع، الهدف (طفل/فئة/تطبيق)، النافذة الزمنية، أيام الأسبوع، الأولوية |
| FR-003 | `rule_detail` | تفاصيل القاعدة وأثرها: من تتأثر الآن ومن سيتأثر لاحقًا |
| FR-004 | `rule_edit` | تعديل القاعدة مع الحفاظ على سجل الإنشاء الأصلي |
| FR-005 | `rule_impact` | شاشة التأثير: الأطفال المتأثرون فعليًا + نافذة التطبيق |
| FR-006 | `rule_child_rules` | قواعد طفل محدد (عرض الوالد + عرض الطفل لنفسه) |
| FR-007 | `rule_execution_log` | سجل قرارات المحرك: كل تقييم Outcome/Sبب صادق ومقروء عكسيًا |

جميع الشاشات مطابقة لنظام التصميم: كحلي `#0F2A5B`، تركوازي `#00B8A9`، بطاقات Material 3 بزوايا 16، خط Cairo، دعم كامل للعربية RTL والإنجليزية LTR، وحالات صادقة (تحميل/فارغ/خطأ/انقطاع/فشل صلاحية).

### 2.2 طبقة الدومين (`lib/domain/family_rules.dart`)

- `RuleKind`: 7 أنواع حية (`dailyScreenTime`, `bedtime`, `homework`, `appBlock`, `categoryBlock`, `locationGeofence`, `emergency`) + 3 محجوزة (`taskGated`, `rewardUnlocked`, `eventOverride`) مع `isExecutable`
- `RuleSchedule` / `RuleScheduleKind` (يومي/أسبوعي/مرة واحدة)
- `RuleConflict` مع winner/loser وتقييم الصرامة
- `PolicyEvaluation` و `RuleExecutionEntry` لسجل القرارات
- `FamilyRule` كامل التحويل من/إلى الخرائط مع تسلسل مجموعات القوائم لنصوص SQLite

### 2.3 طبقة البيانات (`lib/data/family_rules_repository.dart`)

- CRUD كامل فوق جدول `family_rules` الجديد (إصدار قاعدة البيانات **21**) مع رفض الـ IDs المكررة صراحة
- محرك التعارضات `conflictsFor`: تقاطع مداري للنوافذ الليلية فوق دائرة 1440 دقيقة، الأولوية الأعلى تفوز، والتعادل يُحسم بتاريخ الإنشاء
- `applicableForChild`: القواعد الممكنة لطفل محدد فقط
- سجل التنفيذ `logExecution` مع FK حقيقية على `rule_execution_log`
- كل كتابة تُرحَّل إلى `outbox` بمفتاح Idempotency مع معالجة إعادة الإرسال عند وجود صف معلّق (إصلاح خلل الاصطدام في مفتاح idempotency_key)

### 2.4 الصلاحيات والوصول

- سلطتان جديدتان في `FamilyPermission`: `viewFamilyRules` و `manageFamilyRules`
- مصفوفات التفويض محدّثة: الوالد يدير، الزوج يرى، الطفل يرى قواعده فقط
- جميع الفحوصات عبر `FamilyRuntimeContext.can()` — لا إعادة تنفيذ محلية لفحوصات الأدوار

### 2.5 التكامل مع المراحل السابقة

- المحرك مبني فوق بنية الأنماط `mode_configs` (FS-005) وقيود التطبيقات (FS-003) وفئات الويب (FS-002) الموجودة
- الأنواع الثلاثة المحجوزة جاهزة للربط عند تنفيذ FS-007/FS-008/FS-014 (نوع واحد + رابط تنفيذ لكل مرحلة)
- مزودو Riverpod في `guardian_providers.dart` بمزود التعارضات المُشتق من قائمة القواعد

## 3. الأخطاء المكتشفة والمُصلحة خلال الاختبار

| # | الخلل | الإصلاح |
|---|---|---|
| 1 | تسلسل cascades `toList()..sort()..join(',')` يعيد قائمة لا نصًا | التفاف join بقوسين في `FamilyRule.toMap` |

## 4. التحقق والاختبارات

- **اختبارات FS-011:** 13 اختبارًا في 3 مجموعات (بنية قاعدة البيانات v21، CRUD الصادق + outbox، محرك التعارضات، سجل التنفيذ ونطاق الأطفال) — **جميعها خضراء**
- **الانحدار الكامل:** **354/354 أخضر** (341 سابقة + 13 جديدة)، 0 أخطاء `flutter analyze` على lib
- **التوطين:** 94 مفتاحًا جديدًا بصيغة `fr*` في الخريطتين العربية والإنجليزية — الإجمالي **1225/1225** في الخريطتين معًا (تحقق سطر بسطر)
