## ما نُفذ

1. فُحص ملف Android supplied من المالك وتحقق تطابقه مع `com.guardianeye.app`؛ توقف المسار لو ظهر mismatch، لكنه لم يظهر.
2. نسخ الملف إلى الموضع الرسمي `android/app/google-services.json` بصلاحية محلية `0600`، واستبعد من `.gitignore` مع iOS/FlutterFire configurations المحلية.
3. أضيف Google Services plugin إلى `android/settings.gradle.kts` و`android/app/build.gradle.kts` دون تغيير application ID أو Firebase package versions.
4. فُعل مسار Anonymous Auth في wrapper/UI، ويصفه التطبيق كجلسة مؤقتة لا كوالد أو عضو أسرة.
5. ثبت Firebase CLI 15.26.0 وFlutterFire CLI 1.4.1، ثم تفوض CLI بحساب المالك وتحقق من `manus-guardian` قبل أي نشر.
6. ولد FlutterFire ملف options Android رسميًا، وربط bootstrap به دون إدخال قيم يدوية.
7. نشر Firestore rules/indexes، ثم قوى قاعدة أعضاء الأسرة لتجمد `role` و`memberUid` بعد الإنشاء ونشرها مجددًا.
8. نفذ اختبار شبكة حقيقي بحسابات اختبار عابرة: email registration/login/refresh، anonymous auth، family bootstrap/read-back، وست حدود رفض HTTP 403.

## الحاجز التالي: Cloud Functions وFCM

نجح جزء Firebase Auth وFirestore دون الحاجة إلى ترقية فوترة. لكن Firebase CLI أوقف نشر `functions:guardian` قبل التنفيذ لأن Cloud Functions v2 تتطلب Cloud Build وArtifact Registry، وهما يتطلبان خطة Blaze. لا تغير الخطة أو تدخل بيانات دفع تلقائيًا. بعد مراجعة المالك لقرار الفوترة، يكون الأمر الوحيد المطلوب:

```bash
firebase deploy --only functions:guardian --project manus-guardian
```

بعد النجاح، اختبر callable provisioning وincident/SOS triggers على backend، ثم انتقل إلى APK وجهاز Android لتسجيل token وإثبات FCM states منفصلة.
